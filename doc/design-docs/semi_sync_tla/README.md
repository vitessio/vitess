# TLA+ model of semi-sync failover

`SemiSyncFailover.tla` models one shard that runs MySQL semi-sync replication under Vitess. It covers the tablets' mysqld and vttablet, the shard record and its lock, clients writing through vtgate, and one or two VTOrcs. The VTOrcs run EmergencyReparentShard (ERS) and the single-tablet recoveries.

The model follows the code on `main` (`fb653f2`), not an idealized design. The deployment it models:
- three tablets, each in its own cell;
- durability policy `semi_sync`, which needs 1 ACK and lets any REPLICA send it;
- MySQL with `rpl_semi_sync_source_wait_point=AFTER_SYNC`, a timeout of 1e18 and `wait_no_replica=ON`, so the primary never falls back to async;
- `sync_binlog=1`;
- VTOrc with `--allow-emergency-reparent` and `--change-tablets-with-errant-gtid-to-drained`.

Each bug the model found is a `CONSTANT` switch. `TRUE` is the code on `main` and `FALSE` is a fix, so a configuration can reproduce the bug or check the fix.

This is a bounded model check, not a proof. The bounds, and what the model leaves out, are listed below.

## Running it

```
TLA2TOOLS_JAR=/path/to/tla2tools.jar ./run.sh                   # every configuration, checked against its expected outcome
TLA2TOOLS_JAR=/path/to/tla2tools.jar ./run.sh b1_srs_ack        # one of them
./trace.py out/b1_srs_ack.out                                   # its counterexample: each step's action and changed variables
```

`run.sh` runs TLC and prints the outcome of each configuration: no error, or the violated invariant. It also prints the number of workers, the time and the number of distinct states, and exits non-zero on an unexpected outcome.

Environment variables:
- `TLA2TOOLS_JAR` defaults to `tla2tools.jar` next to the script. `.gitignore` keeps that file out of the repository; download it from the [TLA+ releases](https://github.com/tlaplus/tlaplus/releases). The runs below used the rolling `v1.8.0` pre-release built from tlaplus commit `1813307` (2026-10-04), on OpenJDK.
- `TLC_WORKERS` (default 4) sets the worker threads for the configurations expected to pass.
- `TLC_BUG_WORKERS` (default 1) sets them for the configurations expected to violate an invariant. Several of those bugs break more than one invariant, and with several workers TLC reports whichever violation a worker reaches first. With one worker the search is breadth-first and deterministic, so the reported invariant and the state count are always the same.
- `TLC_HEAP` (default `8g`) sets the Java heap.

Configurations are generated by `mkcfg.sh <name> KEY=VALUE...`, and the first line of each `.cfg` is the command that regenerates it exactly. The defaults are the code on `main`, one VTOrc and the base bounds.

## What is modeled

**MySQL (per tablet).**
- **Binary log.** `binlog` is the ordered list of executed transactions; `log_replica_updates` is on. With `sync_binlog=1` it survives a crash.
- **Clients and semi-sync waits.** A client commit is appended to the primary's binlog. With source-side semi-sync on, it then waits for an ACK (`wait`): AFTER_SYNC makes it readable by replicas but not yet acknowledged. With source-side semi-sync off, it is acknowledged at once.
- **Receiver.** It copies the first transaction of its source's binlog that the replica lacks (GTID auto-position) into the relay log. If both sides have semi-sync enabled, it ACKs, and MySQL completes every waiting commit up to that binlog position. A completed commit is acknowledged to its client if the client's session is still alive.
- **Applier.** It executes the head of the relay log.
- **Crash and restart.** A crash makes the waiting sessions fail; crash recovery keeps their commits in the binlog. A restart comes up with `super_read_only`, semi-sync off and replication not started (`skip_replica_start`). With `relay_log_recovery=1`, the unapplied relay log is dropped.
- **Repoints.** `STOP REPLICA` + `CHANGE REPLICATION SOURCE` drops the unapplied relay log when the source changes or a heartbeat interval is given.
- **Durability policy.** `semi_sync`: every PRIMARY or REPLICA tablet other than the primary is an acker, DRAINED tablets are not, and one ACK is needed.

**vttablet.**
- **`DemotePrimary(force)`** (`rpc_replication.go`). It stops serving; the sessions still waiting after the shutdown grace period are killed and their clients get an error. Then it disables source-side semi-sync, which completes those commits, and sets `super_read_only`.
- **`SetReplicationSource`** (`setReplicationSourceLocked`). In order:
  1. A PRIMARY tablet becomes REPLICA without a database action.
  2. It reads the position for the errant GTID check.
  3. `fixSemiSync` disables source-side semi-sync.
  4. It runs the errant GTID check against the new source's executed set, ignoring the source's own GTIDs (`ErrantGTIDsOnReplica`).
  5. It repoints and starts replication.
- **`shard_sync`.** A new primary publishes itself in the shard record, asynchronously. A PRIMARY that sees a newer primary demotes itself and repoints, unless it has errant GTIDs.
- **Replica vttablet restart** (`initializeReplication`). It repoints the replica to the shard record's primary, without the shard lock.

**VTOrc.**
- **ERS triggers.** `DeadPrimary`: VTOrc cannot reach the primary, and no replica it reaches replicates from it. `PrimarySemiSyncBlocked`: the primary waits for ACKs and no semi-sync replica is connected.
- **ERS steps** (`emergency_reparenter.go`, `replication.go`):
  1. Take the shard lock and read the shard record.
  2. `StopReplicationAndGetStatus(IOTHREADONLY)` on each tablet, or `DemotePrimary(force)` on a tablet that is not a replica.
  3. Proceed once N-1 tablets have answered; the rest are cancelled. A cancelled `DemotePrimary` has stopped serving and killed the waiting sessions, then reverts to serving. Revocation is checked as in `haveRevoked`, unless the only failure is the shard record's primary.
  4. Pick a most advanced candidate by executed plus received transactions (incomparable sets abort). It needs a reached acker that it can repoint.
  5. Wait until the candidate has applied its relay log.
  6. Send `SetReplicationSource` to every other tablet, detached, with its own timeout.
  7. Wait until an acker is repointed.
  8. Check the lock, then run `PromoteReplica`: `RESET REPLICA ALL`, source-side semi-sync, read-write, PRIMARY with a new term.
  9. Release the lock.
- **ERS failures.** Any step before the promotion can fail. A failure cancels that ERS's RPCs and restarts the receivers it stopped.
- **Single-tablet recoveries**, each one atomic step under the lock:
  - `fixReplica` repoints to the shard primary; since #21251 only a change of source runs `CHANGE`.
  - `fixPrimary` runs `UndoDemotePrimary` on the shard record's primary.
  - `ReplicaIsWritable`.
  - `StaleTopoPrimary`: force-demote, then repoint.
  - Errant GTIDs → DRAINED.
- **Shard lock lease.** It can expire under a holder that keeps going. Nothing renews it: `topo.Lock` cancels its `KeepAlive` when it returns, and only `CheckShardLocked` (`KeepAliveOnce`) extends it. Under PRS it can therefore only expire while PRS waits, since PRS checks the lock right before each of its quick steps.

**PlannedReparentShard** (`planned_reparenter.go`, the graceful promotion), run by an operator through vtctld, which reaches every tablet:
1. Take the shard lock. Every tablet must answer; the primary-elect is a REPLICA that another tablet can ACK for.
2. Check the lock, then `SetReplicationSource(primary-elect, primary)` and wait for it to reach the primary's position.
3. Check the lock, then `DemotePrimary(force=false)`: stop serving, wait for semi-sync to be unblocked (if commits wait for an ACK it times out, and the tablet reverts to serving), `super_read_only`, disable source-side semi-sync.
4. Wait for the primary-elect to reach the demoted position. If that times out, `UndoDemotePrimary`. If it succeeds, check the lock; if the lock is gone, PRS fails and leaves the primary demoted.
5. `reparentTablets`, with no further lock check: `SetReplicationSource` to the primary-elect on every other tablet, the old primary included, concurrently with `PromoteReplica`. PRS succeeds once a semi-sync replica ACKed the journal and every repoint returned. Any step can fail; a failure in this step cancels the outstanding repoints.
6. Release the lock.

**Network.** Links between tablets, VTOrcs, vtgate and topo can be cut one at a time, or all links of one node at once, and then healed. A cut link drops packets: TCP sessions survive a partition, and a client waiting on a commit is still waiting when the partition heals.

## Properties

| Invariant | Meaning |
|---|---|
| `NoLostAck` | Every acknowledged write is in the binlog of the newest primary, the tablet with the highest primary term. A promotion that loses an acknowledged write violates it. So does a write that a deposed primary acknowledges. |
| `NoUnbackedAck` | Every write was acknowledged while another tablet held it. This is the semi-sync contract. |
| `OneAckingPrimary` | At most one tablet is writable and able to acknowledge: either its semi-sync is off, or a semi-sync replica is connected to it. |
| `NoErrantServingReplica` | Once no reparent or repoint is in flight, no replicating REPLICA holds a transaction that the newest primary lacks. Breaking it costs availability (the tablet is drained), not data. |

## State space

Two reductions keep the state space small without removing any behavior that the invariants can observe:
- **Finished reparents leave no traces.** When an ERS or a PRS releases the lock, its own bookkeeping (`ersOld`, `reached`, `pos`, `cand`, `repointed`; `prsOld`, `prsCand`, `prsPos`, `prsPend`) is reset. Every read of these variables happens while that reparent runs, and the next one overwrites them before reading, so states that differed only in a finished reparent's leftovers were equivalent. They made up a fifth of `current_fixed`'s states.
- **Symmetry.** The tablets other than the initial primary start alike, and so do the VTOrcs, and no action prefers one of them, so every configuration declares `SYMMETRY Symmetry`: TLC keeps one state per class of states that differ only by such a permutation. The only `CHOOSE` over tablets, `Newest`, has a unique answer (every promotion takes a term above all others), so it does not depend on the permutation.

Together they reduce `current_fixed` from 7,105,556 to 1,839,194 states and `orcs2_no_expiry` from 10,280,620 to 534,334 (4.9× from the resets, 4× from symmetry). Every bug configuration still violates the same invariant. A counterexample is a real behavior of the model, possibly with t2 and t3 or the two VTOrcs swapped.

## What is not modeled

- **The other PRS paths.** PRS's initial promotion (no primary yet), its potential promotion (no clear primary), and the VTOrc recoveries that call PRS. Availability: PRS failing and leaving the primary demoted is reachable but not an invariant violation (the chaos runs R2 and R3 measure it).
- **RDONLY tablets, more than three tablets, and other durability policies.** This covers `cross_cell`; with one tablet per cell it behaves like `semi_sync`.
- **Topo outages and cell-local topos** (audit 3B). The topo is one node that can be cut off.
- **vtgate's routing.** Any client can write to any serving, writable PRIMARY it reaches, which over-approximates vtgate's healthcheck (audit 3E).
- **Timing.** Timeouts are nondeterministic failures; there are no clocks.
- **MySQL details.** Semi-sync ACKs are per binlog position, and one receive step both writes the relay log and ACKs. Torn relay logs, partial transactions and `RESET REPLICA` self-heal paths are not modeled.
